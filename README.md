# MYD Shell

### موتور اجرای دستورات و مدیریت پردازش برای Node.js

**MYD Shell** یک پروژه ماژولار مبتنی بر Node.js برای اجرای دستورات سیستم، مدیریت پردازش‌ها، کنترل مسیر کاری و دریافت خروجی اجرای دستورات است. هدف پروژه فراهم‌کردن یک لایه اجرایی قابل‌استفاده در ابزارهای توسعه، برنامه‌های دسکتاپ، سیستم‌های خودکارسازی و عامل‌های هوش مصنوعی (AI Agents) است.

> پروژه در حال توسعه است؛ بعضی قابلیت‌ها هنوز کامل نشده‌اند و پیش از استفاده عملیاتی باید تست و ایمن‌سازی شوند.

---

## امکانات

- اجرای دستورات به‌صورت هم‌زمان (Sync) و غیرهم‌زمان (Async)
- دریافت خروجی استاندارد و خطا (stdout و stderr)
- دریافت زنده خروجی پردازش از طریق رویدادها
- مدیریت پردازش‌های در حال اجرا و شناسه آن‌ها
- توقف پردازش و توقف گروهی پردازش‌ها
- تنظیم زمان مجاز اجرا (Timeout)
- تعیین مسیر کاری برای اجرای دستور
- امکان ارسال متغیرهای محیطی سفارشی
- مدیریت مسیر کاری مجازی و پیمایش پوشه‌ها
- معماری ماژولار برای توسعه و اتصال به ابزارهای دیگر

## استفاده

### اجرای هم‌زمان (Sync)

در اجرای Sync، برنامه تا پایان دستور منتظر می‌ماند:

```javascript
const { ProcessManager } = require('./src/process-manager');

const shell = new ProcessManager();

const result = shell.runSync('echo Hello MYD Shell');

console.log(result.output);
console.log('Exit Code:', result.exitCode);
```

خروجی runSync شامل موارد زیر است:

- stdout: خروجی استاندارد
- stderr: خروجی خطا
- exitCode: کد خروج
- output: خروجی قابل استفاده

### اجرای غیرهم‌زمان (Async)

برای اجرای دستورهای طولانی، مانند اجرای سرور توسعه یا ابزارهای Watcher، از run استفاده کنید:

```javascript
const { ProcessManager } = require('./src/process-manager');

const shell = new ProcessManager();
const proc = shell.run('npm run dev');

proc.on('stdout', (data) => {
  process.stdout.write(data);
});

proc.on('stderr', (data) => {
  process.stderr.write(data);
});

proc.on('exit', (code, signal) => {
  console.log('Process exited:', code, signal);
});

proc.on('error', (error) => {
  console.error('Process error:', error.message);
});
```

### مشاهده پردازش‌های فعال

```javascript
console.log(shell.list());
```

### دریافت پردازش با شناسه

```javascript
const processInfo = shell.get(processId);
console.log(processInfo?.info);
```

### توقف یک پردازش

```javascript
shell.kill(processId);
```

### توقف تمام پردازش‌های تحت مدیریت

```javascript
shell.killAll();
```

## مدیریت مسیر کاری

ماژول CwdManager مسیر کاری را مستقل از مسیر کاری سراسری برنامه مدیریت می‌کند.

```javascript
const { CwdManager } = require('./src/cwd-manager');

const cwd = new CwdManager();

console.log('Current directory:', cwd.cwd);

const result = cwd.cd('../');

if (result.success) {
  console.log('New directory:', result.cwd);
}
```

### دستورات پیمایش

| دستور | عملکرد |
|---|---|
| cd | رفتن به پوشه Home |
| cd path | رفتن به مسیر مشخص |
| cd .. | رفتن به پوشه والد |
| cd ~ | رفتن به پوشه Home |
| cd - | برگشت به مسیر قبلی |
| pwd | نمایش مسیر جاری |
| pushd | تغییر مسیر و ثبت آن در تاریخچه |
| popd | برگشت به مسیر قبلی |
| dirs | نمایش تاریخچه مسیرها |

### توابع مسیر

```javascript
// تبدیل مسیر نسبی به مسیر کامل
cwd.resolve('./project');

// بررسی وجود مسیر
cwd.exists('./project');

// بررسی اینکه مسیر یک پوشه است
cwd.isDirectory('./project');

// فهرست محتویات پوشه
cwd.ls('./');
```

### ذخیره و بازیابی وضعیت

```javascript
const state = cwd.exportState();

// بازیابی وضعیت در نمونه دیگر
const anotherCwd = new CwdManager();
anotherCwd.importState(state);
```

## تنظیمات اجرای پردازش

امکان تعیین مسیر، متغیرهای محیطی و Timeout برای اجرای پردازش وجود دارد:

```javascript
const proc = shell.run('npm run dev', {
  cwd: './project',
  timeout: 300,
  env: {
    NODE_ENV: 'development'
  }
});
```

| گزینه | شرح |
|---|---|
| cwd | مسیر اجرای دستور |
| env | متغیرهای محیطی سفارشی |
| timeout | حداکثر زمان اجرا بر حسب ثانیه |
| shell | فعال یا غیرفعال‌کردن اجرای دستور از طریق Shell |

## امنیت

MYD Shell دستورات سیستم را با سطح دسترسی کاربر اجراکننده برنامه اجرا می‌کند و **به‌تنهایی Sandbox امنیتی محسوب نمی‌شود**.

هنگام اتصال به Agentهای هوش مصنوعی یا اجرای ورودی‌های غیرقابل‌اعتماد:

- ورودی و دستورها را اعتبارسنجی کنید.
- اجرای دستورات حساس را محدود کنید.
- از افشای متغیرهای محیطی و کلیدهای محرمانه جلوگیری کنید.
- دسترسی به مسیرها و فایل‌های حساس را کنترل کنید.
- برای اجرای کد غیرقابل‌اعتماد از ایزوله‌سازی واقعی استفاده کنید.
- قبل از استفاده در محیط Production، رفتار پردازش‌ها و محدودیت‌های امنیتی را بررسی کنید.
